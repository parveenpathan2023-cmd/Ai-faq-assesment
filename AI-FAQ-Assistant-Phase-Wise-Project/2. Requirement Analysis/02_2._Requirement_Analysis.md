# Phase 2 – Requirement Analysis

## Functional Requirements

| ID | Requirement | Description |
|---|---|---|
| FR-01 | Registration | New users can create accounts |
| FR-02 | Login | Registered users can authenticate |
| FR-03 | Profile | Authenticated users can retrieve their profile |
| FR-04 | Create FAQ | Authenticated users can create FAQ records |
| FR-05 | View FAQs | Public users can view all FAQs |
| FR-06 | View FAQ | Public users can retrieve an FAQ by ID |
| FR-07 | Search FAQs | Users can search by question, answer or category |
| FR-08 | Update FAQ | FAQ creator can update their FAQ |
| FR-09 | Delete FAQ | FAQ creator can delete their FAQ |
| FR-10 | AI Answer | Authenticated user can send a question to Gemini |
| FR-11 | AI FAQ | Authenticated user can generate an FAQ from a topic |
| FR-12 | Validation | Request data is validated before processing |
| FR-13 | Error Handling | Centralized API error handling is provided |

## Non-Functional Requirements
- Security through password hashing and JWT
- Maintainable modular architecture
- RESTful API design
- MongoDB persistence
- Appropriate HTTP status codes
- Input validation
- Error logging and handling
- API testability through Postman

## API Requirements

### Authentication
- POST `/api/auth/register`
- POST `/api/auth/login`
- GET `/api/auth/profile`

### FAQ
- GET `/api/faqs`
- GET `/api/faqs/search?q=keyword`
- GET `/api/faqs/:id`
- POST `/api/faqs`
- PUT `/api/faqs/:id`
- DELETE `/api/faqs/:id`

### AI
- POST `/api/ai/answer`
- POST `/api/ai/generate-faq`
